- После успешного импорта MIDI, JSON или аудио показывается уведомление с именем файла. Для MIDI указаны число полученных одноголосных нот и BPM. Уведомление появляется после применения выбранной дорожки, а не после открытия диалога. Повторная загрузка того же файла также подтверждается. При ошибке устаревшее уведомление об успехе убирается.
- При замене мелодии очищаются история правок и выделение старой ноты; позиция возвращается в начало. MIDI получает исходную высоту нот, скорость 1× и нулевое транспонирование. Название файла сохраняется в подписи источника.
- Исправлена пустая колонка справа в вокальном режиме песни. Одноколоночная внешняя раскладка теперь имеет приоритет над общими стилями песни независимо от порядка загрузки CSS и открытия вкладок. Боковая панель аккордов в режиме текста сохранена.
- Длинная кнопка повторного распознавания акапеллы переносится внутри колонки.
- Исправлен ещё один сбой первого импорта при локальной разработке: позднее обнаружение зависимости `soundtouchjs` внутри Web Worker могло инициировать полную перезагрузку Vite. Зависимость теперь явно включена в `optimizeDeps.include`. Проверено с принудительной пересборкой кэша зависимостей (`--force`). [Механизм Vite](https://vite.dev/guide/dep-pre-bundling).

## Задержка: что удалось уменьшить

По умолчанию используется «Быстрый отклик». При звуковом устройстве 44,1/48 кГц окно анализа уменьшено с 4096 до 2048 отсчётов: примерно с 93/85 до 46/43 мс. Опрос выполняется каждые 20 мс вместо прежних 50 мс. На устройствах 96 кГц размер буфера масштабируется, чтобы сохранить достаточное число периодов низкого голоса. Распознавание проверено синтетическими сигналами 70–1046,5 Гц при разных частотах дискретизации, в том числе с усиленной второй гармоникой.

Это параметры анализа, **не измеренная полная задержка** конкретного микрофона или наушников. Реальный результат зависит также от драйвера, аудиоустройства, браузера и нагрузки на страницу. Интервалы JavaScript не являются гарантией точного реального времени.

Если высота на низком или нестабильном голосе скачет, выберите «Устойчивый · длиннее анализ» и включите микрофон снова. Этот режим использует больше данных: окно 4096 отсчётов при 44,1/48 кГц и интервал 40 мс. Режим сохраняется с проектом; старые проекты без этой настройки открываются в быстром режиме.

AudioContext запрашивает интерактивную задержку и использует частоту устройства вместо принудительных 44,1 кГц. Сам `latencyHint: interactive` не гарантирует улучшения: это и так стандартный режим браузера, запрос может быть проигнорирован. Основное изменение программы — короткое окно и частый анализ.

В «Дополнительно» после включения микрофона доступны размер окна, период обновления и оценки задержки входа/выхода, если браузер их сообщает. Отсутствующее значение обозначено как неизвестное. Эти оценки не выдаются за аппаратный замер полного кругового пути.

### Как настроить у себя

1. Начните с быстрого отклика. Выберите нужный микрофон и используйте проводные наушники.
2. «Слышать свой голос» добавляет браузерный мониторинг. Если звуковая карта поддерживает прямой мониторинг, включите его на карте и оставьте этот ползунок в нуле, чтобы не получать два голоса с разным запаздыванием.
3. «Компенсация задержки, мс» только сдвигает точки голоса назад по шкале времени перед оценкой точности. Она не сокращает задержку слышимого звука и не меняет высоту голоса. Начальное значение 100 мс — сохранённая отправная точка, а не автоматическая калибровка.
4. Подберите компенсацию на знакомой короткой фразе. Не пытайтесь получить нулевую слышимую задержку одним этим полем. Значение можно полностью стереть и набрать заново.

Справка API: [AudioContext](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/AudioContext), [baseLatency](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/baseLatency), [outputLatency](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/outputLatency).

## Разбор присланного no name.mid

Файл содержит 1174 завершённые ноты, темп 120 BPM, диапазон F1–B6. После выделения верхнего голоса получается **995 нот**, что совпадает со скриншотом; для нижнего — 901 нота. В обоих вариантах остаётся короткая F1 (MIDI 29) на 177,13125 секунде (2:57), длительностью около 0,116 секунды.

При сдвиге на −12 она превращается в F0 (MIDI 17), ниже поддерживаемого A0 (MIDI 21). Поэтому старый редактор блокировал всю операцию. Эта нота уже находится в исходном файле: предыдущий сдвиг партии здесь ни при чём. Сама по себе такая нота не доказывает ошибку конвертера — это нужно проверить по записи. В MIDI также встречаются высокие короткие ноты; глобальное понижение на октаву не заменяет проверки транскрипции.

Теперь при таком сдвиге появляется окно с количеством мешающих нот, названием первой, временем и результирующей высотой. Можно:

- отменить операцию, сохранив всё;
- нажать «Показать ноту F1»: редактор прокрутится к ней и выделит её для ручной проверки;
- явно удалить мешающие ноты и сдвинуть остальные одной операцией. Кнопка «Отменить изменение нот» восстанавливает и удалённую ноту, и прежнюю высоту всех остальных.

Ноты не удаляются и не ограничиваются по высоте автоматически. Повторный импорт исходного MIDI возвращает исходную мелодию и очищает историю прошлых сдвигов. Аудио в микшере сохраняется, включая выбранный пользователем сдвиг записи в секундах — это отдельная настройка синхронизации.

## Запуск и проверка

Из папки `lad`: `npm ci`, затем `npm run dev`. На Windows при блокировке PowerShell используйте `npm.cmd`. Адрес: `http://localhost:5174`. Перед заменой своей копии экспортируйте библиотеку; её формат и ключ хранения не меняются.

Для проверки: `npm test`, `npm run build`, `npm run test:e2e -- e2e/vocal.e2e.ts e2e/vocalRecovery.e2e.ts e2e/vocalUsability.e2e.ts` (нужен установленный Chromium Playwright). Необязательные проверки личных файлов используют `LAD_MIDI_PATH` и `LAD_ACAPELLA_PATH`; без этих переменных явно пропускаются. Личные MIDI и MP3 в архив исходников не включены.

Сборка и **537 модульных тестов** пройдены. После исправления предварительной загрузки зависимости прошёл полный прогон **21 браузерного сценария** в Chromium, включая присланные MIDI и MP3, первый импорт при холодном старте, повторную замену, сдвиг с отменой, синтетический микрофон и раскладку 390–1920 px. Дополнительно просмотрены светлая главная, тёмный тренажёр, диалог сдвига и мобильная страница. Полная старая E2E-база табулатур и реальные устройства Safari/iOS заново не проверялись. Аппаратная задержка вашего микрофона в миллисекундах удалённо не измерялась.
