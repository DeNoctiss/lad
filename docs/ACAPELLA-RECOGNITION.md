# Распознавание акапеллы: Basic Pitch

## Как попробовать

В «Вокальном тренажёре» откройте редактор и загрузите файл через распознавание акапеллы. В диалоге появился выбор:

- **Basic Pitch · нейросеть + обработка вокала** — новый вариант по умолчанию.
- **Классический · прежний алгоритм** — сохранённый YIN с отслеживанием высоты, для сравнения или при недоступности модели.

Оставьте автоматический диапазон или задайте диапазон голоса. Слишком узкий диапазон исключает настоящие высокие/низкие ноты. Дождитесь уведомления и прослушайте результат с акапеллой. Перед повторным распознаванием сохраните нужную версию в JSON: успешный новый результат заменяет текущие ноты.

Обработку можно отменить. При ошибке модели прежняя мелодия сохраняется. Модель и WASM включены в проект, загружаются с того же сайта. Аудио анализируется на устройстве и не отправляется стороннему сервису; API-ключ и платная подписка не нужны. На слабом устройстве длинная запись может обрабатываться несколько минут. Ограничения сохранены: до 64 МБ и 6 минут.

## Что делает обработка

1. Аудио преобразуется в моно 22050 Гц.
2. Basic Pitch выдаёт вероятности высот и атак.
3. Выбирается одна линия с учётом вероятностей и непрерывности мелодии.
4. Выделяются ноты/паузы, сглаживаются краткие колебания и удаляются нестабильные короткие события. Сильная повторная атака может разделять ноты одинаковой высоты.
5. Время модели переводится из секунд в четвертные доли с текущим BPM, без привязки к сетке пианорола.

Общего сдвига на −12 полутонов нет. Короткий скачок на обертон может подавляться, если исходная высота остаётся поддержанной моделью. Настоящие устойчивые смены регистра сохраняются. Если модель уверенно выбрала другой голос или неверную октаву, исправление не гарантировано.

Скорость/транспонирование сбрасываются после распознавания, как прежде. Аудио не ускоряется от самого выбора алгоритма. Изменение BPM не является способом исправления высоты нот.

Микрофон и AudioWorklet не изменены: нейросеть применяется только к загруженному файлу. Она запускается в отдельном Worker. Отмена/новая загрузка/закрытие завершают обработчик. Промежуточные тензоры освобождаются после каждого окна, чтобы длинные записи не накапливали память инференса.

## Ограничения

Это первая интеграция. Дубли, гармонии, хрип, реверберация и тихие фрагменты остаются неоднозначными. Выделение одной линии не равно отделению ведущего вокалиста. Проверяйте мелизмы и короткие ноты вручную; сглаживание может пропустить часть из них. CREPE/RMVPE в эту версию не включены.

## Код

- `src/lib/vocal/neural.worker.ts` — модель, WASM, окна инференса и управление памятью.
- `src/lib/vocal/neuralPostprocess.ts` — одноголосная линия, временная шкала и сегментация.
- `src/lib/vocal/transcribe.ts`, `yin.ts` — сохранённый классический алгоритм и общая сегментация.
- `src/lib/vocal/jobs.ts` — Worker, отмена и ресемплинг (11025 Гц для старого алгоритма, 22050 Гц для нового).
- `src/components/vocal/TranscriptionDialog.tsx` — выбор алгоритма и диапазона.
- `public/models/basic-pitch/` — модель из @spotify/basic-pitch 1.0.1.
- `public/models/wasm/` — TensorFlow.js WASM 3.21.0.

Версии TensorFlow закреплены совместно; обновляйте их вместе. `vite.config.ts` заранее оптимизирует зависимости, чтобы первый запуск Worker не вызывал перезагрузку dev-страницы.

## Запуск и публикация

`npm ci`, затем `npm run dev`. На Windows при ограничениях PowerShell используйте `npm.cmd`. Для production: `npm run build`, публикация каталога `dist`. Для GitHub Pages укажите корректный `VITE_BASE` и сохраните весь `public/models`: он автоматически копируется в сборку. Через `file://` обработчик не работает — нужен HTTP-хостинг.

При ошибке загрузки модели проверьте, что сервер раздаёт `.json`, `.bin` и `.wasm` как файлы, а не подменяет их HTML-страницей. Классический режим остаётся доступным.

## Проверки и сравнение

`npm test` — модульные тесты. `npx playwright test e2e/neural.e2e.ts` — настоящий инференс на сигнале с известными A3/A4, первая загрузка, повторный импорт, отказ модели и отмена. Перед браузерными тестами установите Chromium: `npx playwright install chromium`.

Для частного сравнения задайте `VOCAL_BENCHMARK_WAV` (абсолютный путь к WAV) и опционально `VOCAL_BENCHMARK_REPORT` (выходной JSON). Отчёт содержит старый результат, обработанный новый и исходные полифонические события `outputToNotesPoly`. Последние используются только для сравнения, напрямую в одноголосный редактор не импортируются. Приватная акапелла в архив не включена.

Результаты проверки «Осени»: [ACAPELLA-COMPARISON.md](ACAPELLA-COMPARISON.md).
